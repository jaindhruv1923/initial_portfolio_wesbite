    1. The Non-Bypassable AI Pull Request Gatekeeper

    🚨 The Real Enterprise Threat:

    An autonomous agent (Devin, Sweep, or Copilot Workspace) opens a PR resolving an issue, but its patch inadvertently introduces a hardcoded database password or imports a hallucinated package (e.g. npm i fast-auth-token-v2) which is registered by an attacker containing a reverse shell.

    🛡️ How KAVACH Solves It:

    KAVACH runs as a required CI/CD check. It inspects the AST diff, runs polyglot syntax validation, checks all package imports against verified registries, and evaluates risk policies. If a threat is detected, it automatically BLOCKS the PR with a line-by-line remediation comment.

    💼 Enterprise ROI:

    Prevents supply-chain attacks and credential leaks from reaching production without slowing down developer velocity.

    Developer IDE • Cursor • Claude Code PRIVACY & COMPLIANCE

    2. Zero-Trust LLM Privacy Proxy & PII Shield

    🚨 The Real Enterprise Threat:

    Developers querying OpenAI, Anthropic, or Gemini paste snippets containing user emails, phone numbers, customer records, or proprietary internal API keys, violating GDPR, HIPAA, and the Digital Personal Data Protection (DPDP) Act.

    🛡️ How KAVACH Solves It:

    Acts as an internal API gateway proxy. Before requests leave the corporate network, KAVACH's Token Vault intercepts the prompt, detects PII and secrets, replaces them with deterministic encrypted tokens, sends the sanitized prompt to the LLM, and detokenizes the code response locally.

    💼 Enterprise ROI:

    Total regulatory compliance (GDPR/HIPAA) while empowering engineering teams to use the latest cutting-edge foundation models.

    KAVACH performs whole-repo AST dependency parsing and Repository-Aware RAG. It computes a graph-theoretic Change Impact score, identifies every impacted file, and enforces multi-LLM consensus verification before permitting high-blast-radius modifications.

    Reduces production regression incidents by over 90% during large-scale automated migrations and refactoring sprints.

    PILLAR 2 Multilingual PII Vault

    Abstract

    Autonomous Agentic AI developers (e.g., SWE-agent, Devin) promise automated bug-fixing, feature implementation, and CI/CD operations. However, deploying unconstrained autonomous agents in enterprise software ecosystems introduces catastrophic vulnerabilities: (i) package hallucinations and "slopsquatting" attacks, where agents invoke non-existent modules subsequently weaponized by adversaries on public registries; (ii) data exfiltration of sensitive identifiers (PII/SPDI) and API credentials into third-party cloud LLM contexts, violating localization regulations such as the Indian Digital Personal Data Protection (DPDP) Act 2023; (iii) unbounded blast radiuses causing cascading breaking changes; and (iv) non-convergent debugging loops.

    To address these vulnerabilities, this paper introduces KAVACH, an enterprise-grade, deterministic, security-governed agentic DevOps framework. KAVACH implements a three-tier lifecycle inspection topology ($Input \rightarrow RAG \rightarrow Patch$) featuring: (1) an Abstract Syntax Tree (AST) Package Hallucination Firewall that statically intercepts imports and audits them against registry caches to prevent supply-chain hijacking; (2) a Zero-Knowledge Token Vault providing reversible identifier de-identification before external API dispatch; (3) an AST-guided semantic change-impact analyzer; and (4) cryptographic CycloneDX Software Bill of Materials (SBOM) generation satisfying SLSA Level 3 provenance. Empirical evaluation across 100 software packages and 100 multilingual developer prompts demonstrates that KAVACH achieves a 100.0% catch rate against package hallucinations, 0.990 F1 on code-mixed Hinglish PII detection, and improves patch validity to 93.4% via sandboxed AST reflexion—all with an overhead of under 47 ms (<2.5% total lifecycle latency).

    Section I: Introduction & Motivation

    The rapid evolution of Large Language Models (LLMs) from passive autocomplete assistants to autonomous, tool-calling software engineering agents represents a fundamental paradigm shift. Modern agentic frameworks are capable of decomposing complex natural language requirements, querying vector databases via Retrieval-Augmented Generation (RAG), editing multi-file software repositories, and generating automated continuous integration (CI) tests.

    Despite their software development capabilities, deploying unconstrained agentic architectures in regulated industrial settings introduces critical security, governance, and supply-chain vulnerabilities: package hallucination, code-mixed PII spillage, and unbounded code drift. KAVACH treats security as a first-class citizen governed directly within the agent's finite state machine.

    Section II: Threat Model & Problem Formulation

    We consider an active adversary $\mathcal{A}$ attempting to exploit autonomous coding agents through package slopsquatting, eavesdropping on LLM cloud API transcripts, or injecting adversarial prompt delimiters. KAVACH formulates continuous risk scoring functions using weighted action risks, entity severity, and Shannon entropy.

    Section IV: Algorithm 1 (AST Package Firewall)

    Formal AST traversal extracting ast.Import and ast.ImportFrom nodes, normalizing module names, checking local project boundaries and standard library modules, querying the verified registry cache, and flagging missing packages before execution.

    Section V: Experimental Evaluation & Baselines

            Q1: "What if a top-tier hacker uses an unknown zero-day exploit that is not in your regex patterns?"
            ↓
          
          
    
            
    
              The Defense: "Ma'am, regex is only our Tier-1 pre-filter for sub-5ms low-hanging fruit. Even if a top hacker bypasses regex with a novel zero-day payload, they hit our Tier-3 Ephemeral MicroVM Sandbox (gVisor)."
            
    
            
    
              The execution sandbox is booted with --network none (zero outbound network egress). Even if the hacker's payload successfully executes os.system('/bin/bash'), the kernel network namespace has no external route. The reverse shell cannot phone home, no DNS packets can escape, and Linux eBPF probes intercept unauthorized syscalls in under 1.2ms. The entire microVM is wiped clean from RAM immediately after testing.
            
    
          
    
        
    

        
    
          
            Q2: "What if the hacker encodes the prompt in Base64 or exotic Unicode to bypass your prompt filters?"
            ↓
          
          
    
            
    
              The Defense: "We implement Canonical Token Normalization as step zero of the pipeline."
            
    
            
    
              Before any policy evaluation or LLM tokenization takes place, KAVACH recursively decodes Base64, Hexadecimal strings, URL encoding, and reverses Unicode bidirectional overrides (such as \u202E). The obfuscated payload is flattened into plain ASCII text, exposing the underlying malicious intent to our Shannon entropy scanner and AST parsers.
            
    
          
    
        
    

        
    
          
            Q3: "Can an attacker steal AWS keys, DB passwords, or PII from the agent's memory?"
            ↓
          
          
    
            
    
              The Defense: "No, because production secrets never enter the LLM's context window."
            
    
            
    
              KAVACH enforces a Zero-Knowledge Token Vault. All Aadhaar numbers, PAN cards, AWS keys, and credentials are stripped and substituted with synthetic pseudonyms (e.g., KAVACH_TOKEN_7F3A) prior to cloud dispatch. Furthermore, we deploy active Honeytoken Canaries—if any malicious prompt attempts to dump memory or environment variables, touching a decoy canary key triggers an immediate hard pipeline abort and alerts the SOC.
            
    
          
    
        
    

        
    
          
            Q4: "How does KAVACH stop AI dependency attacks like slopsquatting?"
            ↓
          
          
    
            
    
              The Defense: "Through our deterministic AST Package Firewall."
            
    
            
    
              LLMs frequently hallucinate package names that attackers subsequently register on PyPI with backdoors. When KAVACH synthesizes code, an AST visitor extracts all import statements and verifies them against the official PyPI JSON REST API. Packages that do not exist or packages registered <30 days ago with zero download velocity are quarantined before any pip install command can execute. In empirical tests, this achieved a 100.0% catch rate across 50 hallucinated packages.
